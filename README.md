# 工具开关与 plan-act 工作法

给 DSH 加两件事，专门照顾本地 9B 这类上下文紧张的小模型：

1. **工具开关**——把所有已注册工具列成可勾选的清单，用不到的关掉。工具定义每轮请求都要重发，关掉一个就少一份 schema，单轮对话更专注。
2. **plan-act 工作法**——先通过多轮对话把问题讨论清楚，拆成一份小步 Markdown 计划（plan），再一步一步执行（act）：每一步交给一个全新的子代理，父会话只收到该步截断后的报告与下一步。上下文不再随任务变长而膨胀，小模型一次只做一件小事，避免「雷霆大思考」把每个任务拖得很长、质量变差。

## 安装

1. **Plugins → Add plugin → 本地目录**，选择本目录（`dsh-tool-slice`）。
2. 在插件列表里确认两行：`tool-slice`（Host，工具开关）与 `plan-act` 预设行（计划-执行工作法）。两行都应是已启用状态。
3. **刷新一次页面**（前端插件在页面加载时装配），然后新开一个会话，预设选择器里会有 **「plan-act」**。已有会话不受影响。

改过插件代码后需要重启 DSH 才会加载新模块（HMR 默认不监视模块根）。**本版新增的对话面板与 `/slice` 指令都需要这一次重启**；只刷新页面能看到插件卡片，但看不到面板。

## 用法一：工具开关（按对话保存）

输入框下方有一条细窄的控制条，不占正文：

- **「工具 34/57」**——点开是本对话的勾选清单：顶部是**情景选择**，中间是分组勾选（可搜索、整组开关、全部开/关），底部是**固定的保存/撤销按钮**（不随滚动消失）。
- **「计划 3/8」**——点开是计划的进度、当前步骤、全部步骤，以及「开始规划 / 执行下一步 / 发给模型修订」按钮。

两个面板都和 DSH 自己的菜单一样**向上弹出**（浮在对话区上方，不会把输入框顶下去），高度按上方剩余空间自适应；点面板外面或按 Esc 收起。

### 工具开关：勾选 → 保存

勾选只是草稿：想试一套组合、看 token 估算、再决定要不要用。点底部的 **「保存本对话」** 才写入，**「撤销」** 回到已保存的状态。按钮固定在整个面板的最底部，工具列表再长也不用滚到末尾去找。

### 每个对话各自保存

开关是**按对话**的，这正是以前互相串味的原因。规则只有一条：

- 在某个对话里保存过 → 这个对话只用自己的清单，标题上显示 **「仅本对话」**；
- 没保存过 → 用**默认**清单，显示 **「跟随默认」**；
- 想丢掉本对话的自定义，点 **「跟随默认」**，它就从状态文件里删掉这个对话的条目。

所以 A 对话关掉网页工具，不会影响 B 对话；`step_run` 拉起的子代理跟着它所属的对话走。

### 情景：在面板里新建，在对话里选中

情景就是一套命名好的工具开关，**直接在对话边的面板里建，也在面板里选**：

1. 勾出你想要的开关组合；
2. 在「给当前这套勾选起个名字…」里填个名字（例如「编码」），点 **「存为情景」**——立即保存，所有对话都能看到；
3. 之后任何对话打开面板，顶部 **「情景」下拉框**里选中它 → 整套开关载入草稿 → 点「保存本对话」。

下拉框里还带三个**内置情景**（按工具分组实时算出来，不写死工具名）：**编码**（关网页/Office/定时任务）、**调研**（关终端/Office）、**极简**（只留读写文件、搜索、待办、询问）。自己存的情景和内置重名时以自己存的为准。

选中自己存的情景时，下拉框旁边会出现 **「删除」**，删掉这个定义（不影响任何对话已保存的开关）。

**Plugins → 本插件 → 配置卡片「工具开关 · 默认与情景」** 是同一个编辑器的完整版：它改的是**默认值**，所以「在页面里选情景 + 点『保存默认』」就等于让所有没单独设过的对话都用这套开关。

保存后的状态在 `%DSH_PROFILE_DIR%\tool-slice.json`（通常 `C:\Users\<你>\.dsh\profiles\desktop\tool-slice.json`），可以直接编辑：

```json
{
  "version": 2,
  "revision": 7,
  "hidden": ["web_search", "office_render"],
  "scenarios": [{ "name": "编码", "hidden": ["web_search", "office_render"], "note": "" }],
  "sessions": {
    "s-9f3c1a2b": { "hidden": ["pwsh", "web_fetch"], "updatedAt": "2026-11-20T22:40:00.000Z" }
  }
}
```

`hidden` 是默认清单，`sessions` 里每个会话一份（最多保留 200 个，按更新时间淘汰最旧的）。旧版只有 `sets` 的文件仍能读，会当作 `scenarios`。

手改这个文件同样有效：**下一个模型步骤**就会按新内容重算工具表，不需要重启。文件写坏时保留上一次生效的清单，不会让会话出错。

生效范围：所有智能体，包括启用前就已在运行的会话（下一个步骤起）和 `step_run` 拉起的子代理。

清单只在**有会话创建过智能体之后**可读：DSH 的工具表是按预设装配的，页面要先看一眼真实会话的工具集；若卡片显示还没清单，点「刷新清单」。

## 用法二：plan-act（计划 → 你设模型和工具 → 确认 → 执行）

计划是**讨论出来的**，而「哪一步用哪个模型、能调哪些工具、什么时候真的开跑」全部由你在面板里定。整条链路是：

1. **先讨论**。你说目标时如果哪里不明确，模型会先用 `ask_user_question` 一次问 1–3 个关键问题（范围、边界、验收标准、哪些文件能动），而不是自己猜。
2. **再规划（plan）**。问清楚后它先调用 `plan_options` 拿到**此刻真正可用的模型清单**和三档权限说明，再用 `plan_write` 把任务拆成 3–8 个**很小**的步骤。**每一步都带两样东西**：
   - `model`：这一步交给哪个子模型执行（`provider/模型id`，留空＝继承父会话）；
   - `access`：这一步给多少权限，只能是 **只读 / 读写 / 全量**（只读＝不能改文件不能跑命令；读写＝能改文件但不开终端、不上网；全量＝不限制）。
   计划写成 `<工作区>\.dsh\plans\plan-<会话后缀>.md`（侧边栏可以直接预览这份 Markdown）。
   > 计划**只能**由 `plan_write` 写入。用 `write` 手写的计划文件面板不认识，也没法确认和执行。
3. **停下等确认**。计划写完模型就停——用不超过 8 行复述要点（带上每步的模型与权限）。此时计划是**未确认**状态。
4. **你核对/调整每一步**。点输入框下方的「计划」→「设定 N 步」，每一步一行：
   - **权限档位**（只读/读写/全量，规划时给定）或「自定义 −N」（你逐项勾过）；
   - **模型**下拉：列出当前 DSH 真正可用的 provider/模型，默认「继承父会话」；
   - **工具**按钮：勾选这一步允许调用的工具（取消勾选＝这一步禁用该工具）。逐项勾选会**替换**掉档位，变成一个自定义清单。
     这两列写进计划文件，`step_run` 执行该步时**只按这里的最终值来**。
5. **点「确认计划」**。这一步是硬闸门：确认之前，模型调用 `step_run` 会被直接拒绝（报错「这份计划还没确认」），拉不起任何子代理。确认后模型才能执行。
6. **逐步执行（act）**。每一步交给一个全新子代理，用你为它选的模型、只带允许的工具；父会话只收到「这一步的报告 + 下一步」。驱动方式三种都行：你自己点「执行下一步」、输入 `/slice next`、或确认后对模型说「开始」。
7. **改计划**。你对计划有意见就写进「发给模型修订」，模型重写整份计划——**已完成的步骤、报告，以及你为各步设的模型/工具都会保留**，但计划会重新变成未确认，需要你再点一次。
8. 全部完成后模型用 5–10 行总结。

于是父会话的上下文大约是：固定提示词 + 每个 step 几百 token，而不是整段工作历史。计划文件是唯一事实来源，中途重启也能接着走。

### 计划文件长什么样

```markdown
# 任务：把登录从 session 换成 JWT 并补刷新

- 会话：s-test1234
- 创建：2026-11-20 23:30
- 进度：1/3 完成
- 确认：2026-11-20 23:41

## 步骤

### 1. 盘点签发点 —— 完成
做什么：读 src/auth，列出所有签发与校验点
完成标准：给出清单
权限：只读
模型：local/Qwen3.8-9B-Q6_K

### 2. 实现签发 —— 进行中
做什么：在 login 路由签 access+refresh
完成标准：单测通过
权限：读写
模型：qiafan/glm-5.3-flash
开始：2026-11-21 00:51

### 3. 跑集成测试 —— 待办
做什么：跑 pytest 并修失败用例
完成标准：全绿
权限：全量
依赖：2

## 记录

### 步骤 1 —— 完成

找到 4 处签发点：login.ts / refresh.ts / middleware.ts / test/auth.ts

### 步骤 4 —— 已取消

已取消（aborted）：用户停止
```

- `- 确认：` 为空（写成 `未确认`）时 `step_run` 一律拒绝；任何一次 `plan_write` 重写都会把它清掉。
- `权限：` 三档之一，执行时展开成这个预设实际挂载工具的具体禁用清单；省略＝全量。
- `模型：` 省略 = 继承父会话；格式是 `provider/模型id`。
- `开始：` 只出现在**正在执行**的那一步：`step_run` 在拉起子代理**之前**就写进去，所以进程崩了、DSH 重启了，你也能看出某一步是“卡在进行中”而不是真的在跑。收尾（成功或失败）会把它清掉。
- `依赖：` 是“必须等这几步完成”的步骤号。依赖没满足的步骤不会被自动选中，也不会被「并行执行」拉进来。手改这个文件也能加/删依赖。
- 状态有五种：`待办` / `进行中` / `完成` / `失败` / `已取消`。被停止的步骤是 `已取消`，它和 `失败` 一样可以被下一步重跑。
- 每次 `step_run` 返回的对话内容里都带一张**全部步骤的状态表**，所以三步的计划在对话里就能看到每一格的状态，不必去翻文件。
- `关闭工具：a, b` 出现在你**逐项勾选**过的那一步（此时 `权限：` 会被清掉，因为粗档位描述不了自定义清单）。
- 这些字段都可以直接手改这个文件，面板下一次读取就会显示手改后的值。

### 对话边上的计划面板

「计划 3/8」面板不用等模型主动调用工具，人可以直接推：

- **计划芯片**：`计划 1/6 ·第 2 步 ·glm-5.3-flash` —— 常驻在输入框下方，不打开面板也能看到**下一步是哪一步、用哪个模型**。
- **统一步骤设置（面板顶部）**：一个权限档位下拉 + 一个工具勾选（「工具 −N」）+ 三个按钮：
  - **应用到全部步骤**：把这套权限/工具一次写到**所有未完成**的步骤上（已完成的步骤不动）；
  - **设为默认**：存成这个 profile 的默认值。以后 `plan_write` 新建的步骤如果没写权限，就从这个默认值开始（会真的记进计划文件，不只是显示）；
  - **收起**：收起这块，只留一行摘要（「当前统一设置：只读 · 关闭 3 个工具」+ 展开按钮）。
- **对话里的「任务」卡片**：plan-act 把计划镜像成会话的 todo 事件（`todo/write`），所以大对话框上方那张「任务 · 1 进行中 · 3 待处理」卡片会跟着每一步变化：规划完是 4 条 `待处理`，某步开跑变 `进行中`，跑完变 `已完成`。这是 DSH 自带的卡片，不需要打开我这个小窗。
- **每一步的实时日志 + 消耗**：只要有步骤在跑，面板里就会出现「第 N 步 · 正在执行」，逐行显示子代理的 `🔧 工具调用`、`✓/✗ 工具结果`、`💬 它说的话`（来自子代理自己的会话事件流）；每步行尾还会显示 `输出 1.2k tok · 12.3 tok/s · 1 分 40 秒`。**跑完的那一步会立刻从小窗消失**：它的过程已经进了对话，小窗只保留“现在在跑什么”。
- **同一份过程也进对话**：每个 `step_run` 的结果里，报告正文后面跟着一整段「第 N 步 · 子代理全过程」，所以在大对话框里就能读到这个子代理从头到尾做了什么，不必开面板。
  > 说明：DSH 的 Web 对话只渲染工具结果的**内容块**（`presentResult` 卡片视图是给编辑器/CLI 桥的，这个 GUI 不消费），所以这段过程必然也进模型上下文。它按 **4000 字符**封顶（与预置的 `tool-result-pruner` 阈值一致）——超过这个长度，压缩器会替模型收窄，读者这边只看到“已截断”标记。
- **自动顺次跑完剩余 N 步**：确认计划后点它，模型会**连续**调用 `step_run` 一步步跑完，**不用你每步点一次**；每一步的报告仍然落在对话里（那是你读结果的地方）。要停就点「停止全部」或 `/slice stop`，已跑的步骤保留，未跑的停在原状。
- **确认计划 / 取消确认**：唯一能放行 `step_run` 的开关（等价 `/slice approve` / `/slice unapprove`）。
- **每一步清单默认展开**：每行 = 序号、**状态**（待办 / 进行中 / 完成 / 失败 / 已取消，各自不同颜色）、标题、**权限档位**、**模型下拉**、**工具**按钮；有依赖的步骤后面标 `依赖 1,3`。规划时模型给的值就在这里，不用再点别的按钮去找。
- **执行下一步 / 重跑第 N 步**：未确认时禁用；当前这一步不是「待办」时按钮变成「重跑第 N 步」（失败、取消、上一轮崩了、重启了都靠它继续）。本步用什么模型、什么权限、什么时候开始，都写在面板顶部的当前步那行和计划文件里。
- **并行执行就绪 N 步**：当有 ≥2 步**依赖都已满足**时出现。点它 = 你确认这批步骤可以同时跑（等价 `/slice parallel`）。依赖没满足的步骤不会被拉进来。
- **停止全部**：有步骤正在跑（或本会话有计划在跑）时出现，点是等价 `/slice stop`：正在跑的子代理全部取消，步骤标成「已取消」——**不算完成**，可以之后「重跑」或「重新规划」。它只停本会话的计划，不会掐掉模型这一轮。
- **开始规划**：写一句想达到的结果点它，等于 `/slice plan <目标>`——模型**先问问题、再拆解、写完停下**。
- **发给模型修订**：等于 `/slice revise <意见>`；模型重写计划，已完成的步骤与你的模型/权限设定都保留，然后需要重新确认。

计划文件里每改一次会在头部多一行 `- 修订：时间（第 N 版）`，方便你看出这是第几版。

### `/slice` 指令

同一条链路在输入框里也能用（`+` 菜单的指令列表里能找到）：

| 写法 | 作用 |
| --- | --- |
| `/slice` 或 `/slice show` | 报告进度、确认状态、当前步骤和全部步骤（含每步的模型） |
| `/slice approve`（或 `/slice 确认`） | 确认计划，放行 step_run |
| `/slice unapprove`（或 `/slice 取消确认`） | 撤回确认，step_run 重新被拒绝 |
| `/slice next` 或 `/slice next 3` | 执行下一个未完成步骤 / 指定第 3 步（需先确认） |
| `/slice parallel` | 同时执行所有依赖已满足的步骤（需先确认） |
| `/slice auto`（或 `/slice 顺次`） | 让模型把剩余步骤**自动顺次跑完**，不在步骤之间停下来问（需先确认） |
| `/slice stop` | 取消本会话正在跑的步骤，标成「已取消」（不结束模型这一轮） |
| `/slice plan <目标>` | 开始讨论：让模型先澄清再写计划，写完停下 |
| `/slice revise <意见>` | 把修改意见交给模型重写计划（已完成步骤保留） |

指令结果只出现在输入框上方的提示里，**不会进入模型上下文**；只有 `plan` 和 `revise` 会追加一条用户消息。

会话 → 计划文件的对应关系记在 `%DSH_PROFILE_DIR%\tool-slice-plans.json`（最多保留 40 个会话），面板只读这份索引，所以刷新页面、没有模型在跑时也能看进度、改设定、确认计划。

## 预设「plan-act」挂了什么

`pwsh`（非 Windows 用 `bash`）、`read/write/edit`、`glob/grep`、`jobs`、`web_search/web_fetch`、`todo_write`、`ask_user_question`、`plan_options/plan_write/step_run`，外加压缩组（阈值比标准预设更早）。没有挂：Office、子代理工具、技能目录、计划模式、workflow、schedule、goal、present。

## 已知限制

- **只能隐藏，不能新增**：plan-act 预设里没挂的工具（Office、子代理、技能等）在该预设的会话里无法用开关打开。需要它们时用标准预设（标准预设同样受工具开关约束）。
- **面板在所有会话都有，但计划工具只在 plan-act 预设里**：在 standard 等预设的会话里点「开始规划 / 执行下一步」，会直接提示「这个会话的预设没有 plan-act 的计划工具」。这不是 bug —— `plan_write`/`step_run` 是预设插件提供的，面板只是读计划文件、确认计划。要用这套流程请新开一个预设选 plan-act 的会话。
- **情景是全局的，开关是按对话的**：情景定义在面板里（所有对话共享），选中后要点「保存本对话」才落到当前对话。
- **面板里的「存为情景」立即保存**：它写的是共享定义，不需要再点保存；「保存本对话」写的才是这个对话的开关。
- **会话 ID 一变就回到默认**：删除会话、fork 出新会话后会得到新的 ID，按对话保存的开关不跟着走，此时显示「跟随默认」。
- **会话开头那次请求不会变**：工具表在请求开头就解析好了；保存后从下一个模型步骤生效，当前这轮请求不受影响。
- **每一步都会多一次完整请求**：plan-act 用更多请求换更稳的输出，简单任务直接做即可（不要在简单任务上也套计划）。
- **自动顺次执行 = 每步一次模型回合**：它不省调用，只省你的点击。想真正省 token 就在计划里把步骤定得更少更大；想省等待就并行（仅对互不依赖的步骤）。
- **「任务」卡片是镜像的，不是模型写的**：`mirrorPlanToTodos` 每次步骤状态变化都 append 一条 `todo/write`。模型自己也调 `todo_write` 时以最后一次为准；`turn/start` 会清空该投影，所以新回合开始时卡片可能短暂消失，下一步一开跑就又出现。
- **token 与 tok/s 是子代理自己的用量**：来自子代理每条 assistant 消息的 usage；父会话自己的消耗不在这里（状态栏里有）。
- **并行是真并行，但共用你的机器**：同时跑的步骤会真的同时改文件、跑命令。互不依赖（不同文件、不同产物）才并行；两条腿都要改同一个文件时请在规划里加依赖。
- **「停止」分两种**：面板的「停止全部」/`/slice stop` 只取消本会话的计划步骤（模型这一轮还能继续说话）；输入框发送键变停止是 DSH 自己的「中断本轮」，它会把整轮连同步骤一起停掉——两条路都会把在跑的步骤标成「已取消」，不会留下假的「进行中」。
- **面板改设定对「正在跑的那一步」无效**：`step_run` 在开始前就把该步的模型和工具定好了；面板的改动从下一次执行生效。
- **模型下拉来自 LLM 服务枚举**：某个 provider 报不出模型列表时，只能选「继承父会话」，或直接手改计划文件里的 `模型：provider/模型id`。
- **计划修订按标题对齐**：重写计划时，已完成的步骤靠**标题相同**才认得出是同一件事。改标题会被当成新步骤（旧的已完成步骤会连同报告追加到计划末尾，不会丢，但会多一行）。
- **子代理深度**：子代理里再调用 `step_run` 会受委派深度限制（默认 1 层）而失败，这是 DSH 的保护，不是 bug。

## 排错：预设显示「加载失败」

预设里的**任何一行**插件激活失败，整份预设就会显示「加载失败」，界面上只能看到这一句话。插件每次激活后会把每个预设的真实诊断写到**开关状态文件旁边**（即 `%DSH_HOME%\tool-slice-presets.json`，通常 `C:\Users\<你>\.dsh\tool-slice-presets.json`；设置了 `%DSH_PROFILE_DIR%` 时则写在该目录）：

```json
{
  "at": "2026-11-20T15:27:42.521Z",
  "presets": [
    { "id": "plan-act", "name": "plan-act", "broken": "" }
  ]
}
```

`broken` 为空表示可正常使用；非空时这里是完整原因，例如：

```
tool-fs-search (@deepseek-ai/dsh-tool-fs-search): invalid config:
  - $.sampleOverCapGlobResults missing required value
```

常见原因是某个插件把某个字段标成了必填，而预设里没写（`sampleOverCapGlobResults`、`allowParallelInProgress` 就是这类）；也可能是某个包名解析不到。按诊断补上 `config` 或修正包名即可，`test/bundle.test.mjs` 里有一条测试专门盯这两个必填字段。

## 开发

```powershell
node test/core.test.mjs       # 计划 Markdown 的读写、切片、分组、token 估算
node test/workflow.test.mjs   # plan_write / step_run 的完整流程（假 ctx + 假子代理）
node test/host.test.mjs       # 工具掩码：清单、默认/按对话保存、情景、下一步生效、失败回退
node test/client.test.mjs     # 前端模块：插槽注册、摘要视图
node test/bundle.test.mjs     # 清单、补丁、locale、图标的一致性
```

（`node --test test/` 会让 Node 起子进程；在受限沙箱里会报 `spawn EPERM`，逐个文件跑即可。）

- `core.mjs`：纯逻辑，可单独测试（计划 Markdown、下一步选择、分组、情景、按对话解析开关、`/slice` 语法、面板视图）。
- `workflow.mjs`：Host 侧的步骤机器（计划文件、子代理、计划索引），工具与指令共用。
- `index.js`：Host 插件，工具掩码（默认 + 按对话）+ 四个 HTTP 路由（`/api/tool-slice/state`、`/save`、`/scenario`、`/plan`）+ 全局 `/slice` 指令。
- `step-tools.js`：预设插件，注册 `plan_write`（plan）/ `step_run`（act）与提示词段落。
- `client.js`：Plugins 页面里的配置卡片（默认与情景）+ 输入框下方的对话面板（`conversation.composer.dock`，本对话的开关与计划）。
